# 架构 v2 — OCR 主导的"原生中文菜单"渲染

## 目标

译文看起来**像菜单一开始就是用中文印的**：无补丁感、无残影、无错位。
同时把单页成本降约一半，并让相同请求零成本复用。

## 现架构的根因病灶

| 顽疾 | 根因 |
|---|---|
| 译文错位/串菜 | VLM 负责输出坐标，而它的坐标每次调用随机漂移 |
| 英文残影/漏盖 | 我们只替换"归属到菜品"的行，归属失败的行原样漏出 |
| 补丁感 | 逐块/逐行贴纸色补丁，与周围纸面有可见边界 |

## v2 管线（LLM 永不输出坐标）

```
矫正照片
  → Vision OCR：全页每一行文字的精确框（编号清单，含标题/菜名/描述/价格/脚注）
  → LLM（gpt-5-mini，Structured Output）输入 = 行清单(编号+原文) + detail:low 参考图
       输出 = 每行 { 行号, 角色, 译文, 所属菜品id, 菜品级信息(价格/标签) }
       角色 ∈ { section_title, dish_name, description, price, other }
  → 渲染器（整页重排，不再打补丁）:
       1. 全页所有文字行一次性擦除（逐行纸色重建，覆盖 100% 文字）
       2. 按 OCR 原位置重排：
          - dish_name：原文 + 下方译名（双语）
          - section_title：原文 + 译名（双语）
          - description/other：纯译文，字号=原行高、颜色=原字色采样
          - price/数字：原样重绘
```

## 为什么根治

- **坐标 100% 来自 OCR 实测** → 漂移、串位、漏盖在结构上不可能发生；
- **全页每一行都被处理**（角色不明的行也会擦除+原样重绘）→ 无残影；
- **整页统一擦除+重排** → 没有局部补丁的边界感；
- 参考图降为 detail:low（语义参考）→ 输入 token 大幅下降；
- 行清单文本远比高清图便宜 → 单页成本预计 $0.03 → ~$0.015。

## 配套决策

1. **模型升级**：默认 gpt-5-mini（视觉+结构化输出，价格约为 gpt-4.1 的 1/8）；
   设置页保留手选。图像生成不变（gpt-image-1 拼图法）——两次实验已证明
   生成式模型排版密集文字必出乱码，与模型新旧无关。
2. **请求缓存**（已落地）：SHA256(图片字节+模型+目标语+prompt版本) → 磁盘缓存；
   配图按 prompt 缓存。开发迭代与用户重扫同一菜单零成本。
3. **数据模型**：新增 `TextLine { box, role, original, translated, dishID }`
   随 MenuScan 持久化；菜品列表从行清单聚合得出（列表页/点单不受影响）。

## 迁移路径

- Phase 1：OCR 行清单 + 新 prompt/schema + 渲染器整页重排（画布/PDF 版式页）。
- Phase 2：菜品聚合替换现有 items 通道（列表/购物车/配图沿用）。
- 旧扫描（items 结构）继续用 v1 渲染路径展示，不迁移。
